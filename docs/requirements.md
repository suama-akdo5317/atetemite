# あててミテ！ 要件定義書

- ステータス: レビュー待ち
- 設計: [design.md](./design.md)
- 最終更新: 2026-10-17

## 1. 概要

スマホ1台をおでこにかざして遊ぶ、お題当てジェスチャーゲームのブラウザ版。
スマホアプリ「おしえてポン！」の遊び方を参考にする。

## 2. 利用シーン

- 2人以上が同じ場所に集まって遊ぶ。使う端末はスマホ1台。
- 回答者はスマホを横向きにしておでこにかざす。画面は回答者以外に向いている。
- 出題者（回答者以外の全員）は画面のお題を、ジェスチャーや言葉で回答者に伝える。
- 回答者はスマホを前に倒すと正解、後ろに倒すとパスになり、次のお題へ進む。

## 3. 用語

| 用語 | 意味 |
|---|---|
| 回答者 | スマホをおでこにかざし、お題を当てる人 |
| 出題者 | 回答者にお題を伝える人たち |
| お題 | 当てる対象の言葉（例: 「キリン」） |
| カテゴリ | お題のまとまり（例: 「動物」） |
| ラウンド | 制限時間1回分のプレイ |

## 4. 機能要件

### 4.1 ゲーム（クライアント）

| ID | 要件 |
|---|---|
| FR-01 | カテゴリ一覧から1つ選んでラウンドを始められる。カテゴリとお題はDBから取得する。 |
| FR-02 | 制限時間を秒単位で入力できる。範囲は10〜300秒の整数で、初期値は60秒。範囲外や整数以外は開始できず、エラーを表示する。 |
| FR-12 | 問題数を入力できる。範囲は1〜50の整数で、初期値は8。範囲外や整数以外は開始できず、エラーを表示する。カテゴリのお題が指定数より少なければ、あるだけ出す。 |
| FR-03 | ラウンド開始前に「3・2・1」のカウントダウンを表示する。 |
| FR-04 | 選んだカテゴリからお題をランダムに1つずつ表示する。同じラウンド内では同じお題を出さない。文字は離れた場所からでも読める大きさにする。 |
| FR-05 | 傾き操作: 前に倒すと正解、後ろに倒すとパスとして次のお題へ進む。端末をおでこの位置に戻すまで次の判定はしない（連続誤判定の防止）。 |
| FR-06 | タップ操作: 画面の右半分のタップで正解、左半分のタップでパスとする。傾き操作と同時に使える。傾きセンサーが使えない、またはセンサーの利用を許可されなかった場合は、タップだけで遊ぶ。 |
| FR-07 | 残り時間を表示する。0秒になったらラウンドを終える。 |
| FR-08 | 指定した問題数（FR-12）を出し切った場合は、残り時間があってもラウンドを終える。 |
| FR-09 | 正解・パス・残り5秒・終了の各タイミングで効果音を鳴らす。振動に対応した端末では振動もさせる。 |
| FR-10 | 結果画面に正解数と、出したお題の一覧（正解かパスか）を表示する。「もう一度」と「カテゴリ選択に戻る」を選べる。 |
| FR-11 | DBからカテゴリやお題を取得できないときは、エラーメッセージと再試行ボタンを表示する。端末へのキャッシュや内蔵お題によるフォールバックは持たない。 |

### 4.2 お題生成（バッチ）

| ID | 要件 |
|---|---|
| FR-20 | バッチがLLMでお題を作り、DBに保存する。初版はCLIからの手動実行とし、定期実行はあとで追加する。 |
| FR-21 | 同じカテゴリ内で重複するお題は保存しない。 |
| FR-22 | 作ったお題は保存前に機械的にチェックする（空文字、文字数の上限、NGワード）。 |
| FR-23 | バッチが失敗してもゲーム側は既存のお題で遊べる（バッチとゲームは疎結合にする）。 |
| FR-24 | お題を作るカテゴリは、運営が管理する固定リストとする。初版は最低限のカテゴリ数で始める。 |
| FR-25 | FR-22 のチェックを通ったお題はすぐに公開する。お題には公開フラグを持たせ、問題のあるお題はフラグを外して非表示にできる。ゲームは公開中のお題だけを取得する。 |
| FR-26 | 使うLLMのモデルは環境変数で切り替えられる。初期値は Claude Haiku 5.5（`claude-haiku-5-5`）。 |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | 対応環境は iOS Safari と Android Chrome の最新版。PC ブラウザはクリック操作で動けばよい（動作確認・開発用）。 |
| NFR-02 | HTTPS で配信する（iOS で傾きセンサーの許可を求めるのに必要）。 |
| NFR-03 | プレイ中は画面がスリープしないようにする（Wake Lock API。対応していない端末では諦める）。 |
| NFR-04 | カウントダウンとプレイの画面は、常に横向きで表示する。端末が縦向き（画面の向きのロック中や、PC の縦長ウィンドウ）のときは、画面を90度回転させて横向きに表示する。 |
| NFR-05 | ゲーム側からLLMは呼ばない。ゲーム側のDBアクセスは読み取りだけにする。 |
| NFR-06 | ログインは不要。個人情報は扱わない。 |
| NFR-07 | LLMのAPIキーなどの秘密情報は、バッチサーバーの環境変数かシークレット管理で持つ。クライアントには一切置かない。 |

## 6. スコープ外（初版）

- 録画機能（次の版で検討する）
- 複数端末の同期、オンライン対戦
- ログイン、プレイ履歴、ランキング
- ユーザーが作るカテゴリ
- ユーザー操作をきっかけにしたAI生成

## 7. 将来の拡張（検討中）

### 7.1 カテゴリ要望フォーム

1. ユーザーがフォームから「こんなカテゴリがほしい」と要望を送る。
2. 要望はスプレッドシートに出力される（Googleフォーム標準の連携を想定）。
3. バッチがスプレッドシートを読み、カテゴリとして採用するかをLLMが判断する。
4. 採用されたカテゴリのお題を、通常のバッチ処理で作る。

前提条件:

- 要望文は信頼できない入力として扱う。LLMには指示ではなくデータとして渡す（プロンプトインジェクション対策）。
- LLMが採用したカテゴリ名とお題も、FR-22 のチェックを通してから保存する。
- 処理済みの要望は、二重に処理しないよう記録を残す。
